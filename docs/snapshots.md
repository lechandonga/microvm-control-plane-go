# 快照与回滚规则

## 磁盘模型

- 每台 VM 有一张稀疏块表：`块序号 -> 内容 ID`。内容 ID 是块字节的 SHA-256，
  全局内容寻址去重（块内容存于 WAL/快照中的 blob 池）。
- 模拟客户机写入：`WriteBlock(vm, index, data)`，仅允许在 `Stopped/Running`。

## 快照（COW）

- `TakeSnapshot` 在稳定态捕获当前块表的**稠密向量**（每个序号对应的内容 ID）
  和时间戳，作为一个不可变快照整体落盘（`snap_created` 单事件）。
- 此后覆盖某块：新内容得到新 ID，旧内容仍被快照引用而被保留；该旧块若已
  不属于活动磁盘，就作为该快照的 COW 增量计入宿主机磁盘账目。
- 运行中打快照：电源状态保持 `Running`，快照捕获的是事件落盘那一刻的块表。
- 已停止也可以打快照；快照操作与生命周期操作互斥（同 VM 串行槽）。

## 回滚（时间点一致）

- `Rollback(vm, snapshotID)` 把活动块表**整体替换**为快照向量：
  - 快照时存在的块恢复为原内容；
  - 快照之后新增的块消失；
  - 快照之后的覆盖还原。
- 替换是单个 `rolled_back` 事件，任何后续读都只能看到快照时间点或更旧的数据，
  绝不会混入回滚之后才写入的数据。
- 回滚不会删除其它快照：可以在 `snap1 -> snap2 -> snap1 -> snap2` 间反复跳转，
  每个快照仍是独立有效恢复点。
- 运行中回滚：模拟后端做一次“冻结/恢复”电源循环，结束时仍为 `Running`；
  已停止回滚后仍为 `Stopped`。

## 隔离

- 块表、快照表按 VM 分命名空间；一台 VM 的写、快照、回滚、删快照只改自己的
  事件流与块表，测试 `TestRollbackWhileRunning` 验证邻居 VM 的内容完全不受影响。

## 删除与空间回收

- `DeleteSnapshot` 删除一个快照向量；删除后，仅被它（们）引用的内容块不再
  被任何快照或活动磁盘引用，其字节在下次重算账本时完整回收。
- 删除不存在的快照：提交时同步返回 `ErrSnapshotNotFound`。
- Destroy VM：快照随 VM 一起删除，占用全部释放。

## 容量联动

快照占用计入宿主机磁盘（见 `docs/capacity.md`），因此“打快照 → 写新数据 →
删快照”全过程都有可核对的账目，且快照与 Start/Destroy 并发时由每 VM 串行槽
保证不会读到瞬态状态。
