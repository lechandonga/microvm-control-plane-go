# 容量核算与放置规则

容量账目**不做增量维护**：任何时候查询（`HostUsages`）都从权威状态
（VM 列表 + 快照 + 内容块池）重新计算，因此账目不可能与实际存在的
VM/快照漂移。校验规则就是：已用 + 新增 <= 容量。

## 账目口径（每台宿主机）

- **磁盘**：
  - 每台已放置的 VM 预留其 spec 声明的 `disk_bytes`，从 Define 成功直到
    Destroy 完成（Stop 不释放，因为磁盘还在）。
  - 快照额外只计 **COW 增量**：被该主机上的快照引用、但已不属于任何活动磁盘
    的内容块，按块实际字节数计费。同一块被多个快照引用只计一次。
  - 回滚后，仅被快照保留的块集会变化，账目随之自动增减。
  - 删除快照后，不再被任何快照引用的增量块立刻完全回收。
  - **磁盘永远不超卖**（超配比固定为 1）。
- **CPU / 内存**：
  - 只在运行态计入：`Starting/Running/Stopping/Restarting`。
  - `Stopped` 不占 CPU/内存，只占磁盘；因此可以放置超过物理核数的关机 VM。
  - 有效额度 = 物理容量 × 超配比（`OvercommitRatio.CPU/Mem`，默认 1.0）。

## 放置（Define）

- first-fit：宿主机按 ID 排序，第一台 `DiskFree >= spec.disk_bytes` 的主机中标。
- 放置只硬约束磁盘；CPU/内存不预留。
- “判定 + 落盘 placed 事件”在存储锁内原子完成（`PlaceAtomically`），
  并发 Define 的结果不可能超过物理磁盘。
- 放置失败：操作 `Failed`（`ErrCapacityExceeded`），VM 停留在 `Pending`，
  **不占用任何资源**，同规格可重试。

## 启动（Start）准入

- Start 工作流在迁入 `Starting` 前，用**当时重算**的账本校验目标主机：
  `CPUFree >= vcpu` 且 `MemFree >= memory`（按超配比折算）。
- 不满足则操作失败、VM 保持 `Stopped`，不产生任何资源占用；扩容或等其它
  VM 停止后可重试。
- 校验与执行在该 VM 的串行槽内完成，并发 Start/Stop 不会重复计费。

## 释放

| 动作 | CPU/内存 | 磁盘预留 | 快照增量 |
| --- | --- | --- | --- |
| Stop | 立即释放 | 保留 | 保留 |
| Start | 开始计入 | 已保留 | 保留 |
| Destroy（成功） | 全部释放 | 全部释放 | 随 VM 全部释放 |
| 删除快照 | 无关 | 无关 | 唯一引用块完整回收 |
| 回滚 | 无关 | 无关 | 按新的活动磁盘重算增量 |

`mvctl` 演示在销毁全部 VM 后打印的账目为 `cpu 0 mem 0 disk 0`，可直观验证
“拿了多少、还多少”。
